# Scout: закрытый раздел игроков с графиками и сравнением

Дата: 2026-11-18. Статус: черновик, ждёт одобрения.
Продолжает [этап 3](./2026-11-16-stage-3-player-probabilities-design.md): там экран Compare вынесен в «следующий этап». Общие ограничения продукта (не игра, нет призов, факт и прогноз всегда помечены, платный AI за кредиты) описаны там и здесь не повторяются.

## Зачем

Залогиненный пользователь собирает команду и хочет понять, какого игрока взять. Публичные `/players` и `/players/[id]` отвечают на «что с игроком сейчас», но не помогают выбрать между двумя кандидатами и не показывают игрока на фоне остальных. Нужен закрытый раздел, где игрока видно глубже, а двух-трёх кандидатов можно положить рядом, как товары в e-commerce.

Публичные страницы остаются витриной и SEO-воронкой. Решение заказчика: «публичные оставить, внутри сделать глубокую версию». Раздел даёт регистрации причину быть, но ничего у публичных страниц не отнимает.

## Что получает пользователь

Раздел `/scout` в платформе (пункт «Players» в сайдбаре ведёт сюда). Путь не `/players`: он занят публичной страницей из группы `(marketing)`.

### 1. Список `/scout`

Таблица всех игроков с поиском, фильтрами (позиция, клуб, цена) и сортировкой по тем же показателям, что в публичной, плюс очки за £m. У каждой строки чекбокс «Compare». Внизу липкий трей: выбранные игроки, кнопка «Сравнить» (от 2 до 3 игроков). Строка открывает профиль.

### 2. Профиль `/scout/[id]`

Всё, что есть в публичном профиле (блок «Следующий матч», объяснение, форма, минуты, последние матчи, AI-разбор), плюс:

| График / блок                            | Вопрос, на который отвечает                                                       | Факт или прогноз |
| ---------------------------------------- | --------------------------------------------------------------------------------- | ---------------- |
| Radar по позиции                         | «Чем он силён на фоне игроков своей позиции?» Оси, перцентили 0–100               | факт             |
| Очки за £m                               | «Окупает ли он свою цену?» Расчётные очки сезона на £m, место среди своей позиции | факт             |
| xG и xA против голов и ассистов за сезон | «Ему везёт или он реально опасен?»                                                | факт             |
| Ближайшие 5 матчей с ожидаемыми очками   | «Когда его брать?»                                                                | прогноз          |
| Кнопка «Add to compare»                  | кладёт игрока в трей / открывает сравнение                                        |                  |

### 3. Сравнение `/scout/compare?ids=a,b,c`

- Заголовки-карточки игроков (клуб, позиция, цена, статус доступности).
- **Один radar с наложением** (до 3 игроков, цвет и форма линии различаются).
- **Таблица рядом**: цена, форма, очки за £m, голы, ассисты, xG, xA, минуты, P(гол), P(ассист), P(старт), xPts. Лучшее значение в строке подсвечено (не только цветом). Нет данных — «—» с причиной, не 0.
- Графики по игрокам: форма за 10 матчей и xPts на ближайшие 5 матчей, наложением.
- Ссылкой можно поделиться: состав сравнения лежит в URL.

Сравнивать можно только игроков одной позиции (оси radar разные у GK, DEF, MID, FWD, смешивать нечестно). Трей не даёт добавить игрока другой позиции и говорит почему.

## Цели

1. Раздел доступен только залогиненным и в проде, и локально.
2. Игрока видно на фоне позиции (radar, очки за £m), а не только его собственные цифры.
3. Сравнение 2–3 игроков одной позиции: radar, таблица, графики; состояние в URL.
4. Публичные страницы, sitemap и SEO не меняются.

## Не цели и анти-цели

- Нет итогового «балла» или вердикта «бери этого». Продукт даёт аналитику, а не совет; сводная оценка требовала бы выдуманных весов. Лучшее значение подсвечено, решение за пользователем.
- Нет графика истории цены: в базе только текущая и базовая цена сезона.
- Нет импорта команды, планировщика трансферов, AI внутри сравнения. Платный AI-разбор остаётся только на профиле, как сейчас.
- Нет новых зависимостей: recharts уже есть, у него есть RadarChart.
- Анти-цель: показать число, которое проверку не прошло. Любой показатель за закрытым gate остаётся скрытым и в закрытой версии.

## Ограничения

- Архитектура: Controller → Service → Repository, внедрение через `container.ts`, роуты как однострочные делегаторы, auth через `requireUserId`, валидация `parseQuery` (см. `docs/server-architecture.md`). FSD: `app → views → widgets → features → entities → shared`.
- Правила честности этапа 3 действуют целиком: факт и прогноз помечены, закрытые gate-ом числа скрыты как `null`, цена показывается только свежая (не старше 3 дней), расчётные очки без бонусных.
- Графики на `ChartFrame` (вопрос, легенда, форма маркера помимо цвета, таблица для скринридера), читаемо на 375 px, тёмная тема.
- `src/proxy.ts`: `/scout` не добавляется в `PUBLIC_PATHS`; layout платформы уже редиректит без сессии. API проверяет сессию сам.

## Подходы

Выбран **A: раздел `/scout` из трёх страниц** (список с треем, профиль, страница сравнения с `?ids=`).

- B (один экран-воркспейс, сравнение во вкладках): меньше страниц, но тяжёлый клиентский экран, нет ссылки на сравнение, плохо на телефоне.
- C (перенести публичный профиль в приложение + выбор второго игрока): дёшево, но сравнение слабое; заказчик просил его всерьёз.

## Решения, принятые мной (проверьте)

1. Путь `/scout`, `/scout/[id]`, `/scout/compare`.
2. Сравнение только внутри одной позиции, максимум 3 игрока.
3. Radar: перцентиль среди игроков той же позиции с минимумом минут (стартовое значение 450, константа в `params`); ниже порога игрок помечен «мало данных» и radar для него не рисуется. Оси: FWD и MID: голы/90, xG/90, ассисты/90, xA/90, удары в створ/90, ключевые передачи/90. DEF: защитные действия/90, выигранные единоборства %, доля сухих матчей, ключевые передачи/90, голы+ассисты/90. GK: сейвы/90, пропущено/90, доля сухих матчей, пенальти отбито. Точный набор уточняет builder по реально заполненным полям.
4. Список грузит всех игроков одним запросом и фильтрует на клиенте, как `/api/builder/pool` (пул уже собирается так).
5. Состояние трея живёт в клиенте страницы списка, на страницу сравнения уходит через URL.
6. Новые API: `GET /api/scout/players`, `GET /api/scout/players/[id]`, `GET /api/scout/compare?ids=`. Новый `ScoutController` и `ScoutService` строятся поверх существующих `IStatsService` / `IStatsRepository`, как `BuilderService` (прецедент). Недостающие запросы к данным (единоборства, дриблинг и т.п.) добавляются в репозиторий статистики; изменений схемы БД не планируется.

## Что оставлено builder-у

Точные оси radar по заполненным полям, форма DTO, имена файлов внутри слоёв, дизайн таблицы на телефоне (горизонтальный скролл или карточки), кэширование ответа списка, тексты пустых состояний.

## Проверка

- Vitest: чистые функции (перцентили, per-90, подсветка лучшего значения, правила «та же позиция»), сервис на подменённых репозиториях, как `stats.service.test.ts`, компоненты в стиле `probability-card.test.tsx`.
- Ручная и e2e: без сессии `/scout`, `/scout/[id]`, `/scout/compare` редиректят на `/sign-in`, API отвечает 401; публичные `/players` без входа открываются как раньше.
- `npm run lint` и `npm test` зелёные.
