# Этап 3 — Вероятностная аналитика игроков и матчей

Дата: 2026-11-16. Статус: черновик, ждёт одобрения.
Продолжает [этап 1](./2026-11-15-analytics-pivot-design.md) и [этап 2](./2026-11-15-stage-2-epl-analytics-design.md). Общие ограничения продукта (не игра, нет призов, платный AI за кредиты) описаны там и здесь не повторяются.

## Зачем

Заказчик хочет, чтобы основой продукта была прогнозная аналитика: открываешь игрока и понимаешь, чего от него ждать в следующем матче и почему. Вопрос пользователя: «кого стоит брать и насколько вероятен результат». Состав и трансферы собираются потом, на основе этой аналитики, и в этот этап не входят.

Этап 2 дал прогноз ожидаемых очков на один тур. Сейчас на странице игрока одно число и разбивка по компонентам. Нет вероятностей, нет xG, нет графиков, нет горизонта дальше одного тура.

## Что получает пользователь

Центральный экран — **карточка игрока** (публичная страница `/players/[id]`, без входа, рендерится на сервере, как сейчас).

Блок «Следующий матч» (прогноз, явно помечен как прогноз):

| Показатель                         | Пример |
| ---------------------------------- | -----: |
| Забьёт хотя бы один гол            |    42% |
| Сделает хотя бы один ассист        |    23% |
| Выйдет в старте                    |    88% |
| Ожидаемые минуты                   |     78 |
| Ожидаемые фэнтези-очки             |    5,8 |
| Его команда победит (ничья / пор.) |    61% |

Рядом с блоком: источник, метод (ссылка на «Как считаем»), время расчёта и версия модели.

Под ним — короткое объяснение из 1–3 фраз, каждая опирается на факт с числом: «Регулярно играет: 9 стартов из 10», «Первый в очереди на пенальти», «Соперник пропускает 1,8 ожидаемого гола за матч, 4-й худший показатель лиги».

Графики (каждый отвечает на один вопрос):

1. **Форма за последние 10 матчей** — «он забивает по делу или везёт?». Голы против xG, ассисты против xA, по матчам. Факт.
2. **Вероятность гола в следующих 5 матчах** — «когда его брать?». Столбец на матч, подпись соперника и дома/в гостях. Прогноз.
3. **Распределение фэнтези-очков в следующем матче** — «насколько он рискованный?». Вероятности 0–2, 3–5, 6–9, 10+ очков. Прогноз.
4. **Игровое время** — «его ротируют?». Минуты по матчам, старт или выход на замену отмечены формой маркера, а не только цветом. Факт.

Ещё в этапе:

- **Таблица игроков** (`/players`): новые колонки P(гол), P(ассист), P(старт), ожидаемые очки на следующий матч; сортировка и фильтры по ним.
- **Матчи** (`/fixtures`): по каждому матчу ближайших туров вероятности победы, ничьей и поражения. Плюс тепловая карта «клуб × следующие 5–8 туров» с числом в каждой ячейке (ожидаемые голы клуба или вероятность сухого матча, переключатель). Двойные туры — две строки в ячейке, пустые туры — явная пометка «нет матча».
- **«Как считаем»**: метод, веса, качество каждой вероятности против базовой линии и график калибровки («когда мы говорим 40%, событие случается в N% случаев»).
- **Тёмная тема на весь сайт**, акценты зелёный и фиолетовый.

## Цели

1. Модель выдаёт по каждому игроку на каждый из 5 ближайших матчей его команды: P(гол ≥ 1), P(ассист ≥ 1), P(старт), ожидаемые минуты, ожидаемые очки, распределение очков по корзинам; по каждому матчу — P(победа / ничья / поражение).
2. Каждая вероятность проверяется на прошлых турах и показывается, только если проверку прошла.
3. Карточка игрока с блоком прогноза, объяснением и четырьмя графиками.
4. Таблица игроков и страница матчей с вероятностями; тепловая карта календаря.
5. Тёмная тема.
6. Везде видно, где факт и где прогноз, источник и время обновления.

## Не цели этапа

- Импорт команды по FPL Team ID, «Моя команда», планировщик трансферов, сценарии, фишки, сравнение составов, дашборд с рекомендациями. Это следующий этап, у него будет свой дизайн. Данные для импорта проверены (см. «Найдено»), чтобы не потерять.
- Экран Compare (2–4 игрока). Следующий этап.
- Букмекерские коэффициенты на сайте в любом виде.
- Своя модель xG: xG и xA берём готовые у FPL.
- LLM в объяснениях. Объяснения собираются из шаблонов по данным. Платный AI-разбор игрока (10 кредитов) остаётся как есть.
- Другие лиги.

## Провал, даже если «работает»

- Показана вероятность, которая не прошла проверку, или проверка сделана с подглядыванием в будущее.
- Отсутствующее значение показано нулём (например, xG за прошлый сезон, которого у FPL нет).
- Прогноз визуально не отличается от факта.
- Смысл графика передаётся только цветом.
- На сайте появились коэффициенты, ставки или слова, похожие на беттинг.
- Двойной тур показан как один матч, пустой тур — как матч с нулём.
- Публичные страницы ходят во внешние API на каждый заход.
- Модель v2 ломает текущий прогноз очков: если v2 не прошла планку очков, остаётся v1.

## Решения заказчика

- Это новый этап premierfantasy.net, а не отдельный продукт.
- Фокус — вероятности по игрокам и матчам. Состав и трансферы — дополнительные функции позже.
- Источник вероятностей — своя модель (вариант 1). Букмекерские коэффициенты не используются и не показываются. Причина: один проверяемый метод на все 5 матчей и нет повода для платёжного провайдера считать сайт азартным.
- xG/xA из FPL теперь берём (отменяет решение этапа 2 «xG из FPL не берём»): без них нет графика формы.
- Для каждого прогноза указывать источник, метод и дату обновления; факт отделять от прогноза.
- Язык интерфейса — английский, как весь сайт (этап 1: «язык сайта английский, как сейчас»). Все новые подписи, объяснения, графики и страница «How we calculate» на английском, числа в формате 5.8. Русский перевод сайта в этот этап не входит. Тексты в этом документе (названия показателей и страницы «Как считаем») — рабочие, на сайте они английские.

## Подходы, которые рассматривались

1. **Своя модель, усиленная xG/xA и стартами из FPL** (выбран). Один метод на все 5 матчей, проверка калибровки на прошлых турах. Минус: менее точна, чем рынок.
2. **Модель + коэффициенты на ближайший матч.** Точнее на один матч, но два метода на одном графике, рынок «забьёт» только у Bet365, нет рынка «ассист», коэффициенты есть лишь на ~неделю вперёд, и возвращается риск «азартного сайта» у платёжного провайдера. Отклонён.
3. **Только коэффициенты.** Не покрывает 5 матчей, ассисты и старты. Отклонён.

## Решения исполнителя (не обсуждались, можно оспорить)

- **Модель `ewma-poisson-v2`** развивает v1 (`src/server/prediction/lib/model.ts`):
    - частота голов и ассистов на 90 минут — смесь фактических голов/ассистов и xG/xA (вес смеси подбирается на прошлых турах), со сжатием к средней по позиции, как сейчас;
    - P(гол ≥ 1) и P(ассист ≥ 1) — пуассоновские из ожидаемого числа с учётом ожидаемых минут и силы атаки команды против обороны соперника (уже есть в `team-strength.ts`);
    - P(старт) — взвешенная доля стартов в последних матчах команды × доступность (статус травмы FPL), как сейчас считается P(выход);
    - ожидаемые минуты: при старте и при выходе на замену отдельно;
    - распределение очков — симуляция (Монте-Карло) событий матча по тем же частотам и правилам очков FPL; ожидаемые очки остаются откалиброванными, как в v1;
    - победа/ничья/поражение — две независимые пуассоновские величины ожидаемых голов команд (из `team-strength.ts`);
    - горизонт — 5 ближайших матчей команды (не туров): двойной тур даёт два матча, пустой тур — ноль.
- **Планка для вероятностей.** Для каждого показателя отдельно, walk-forward (прогноз на тур N только по данным до тура N), только по фактам FPL текущего сезона, не меньше 8 туров:
    - бинарные события (гол, ассист, старт): оценка Брайера модели лучше базовой линии «доля таких матчей у игрока за его последние 10 матчей команды»;
    - исход матча: Брайер лучше базовой линии «частоты побед хозяев, ничьих и побед гостей в лиге»;
    - распределение очков: многоклассовый Брайер лучше базовой линии «распределение очков игрока в его последних 10 матчах»;
    - отдельно для горизонта 1 (следующий матч) и 2–5 (дальние матчи): если дальние не прошли, на карточке показывается только следующий матч;
    - калибровка входит в планку: калибровочная таблица по корзинам (0–10%, 10–20%, …) хранится и публикуется на «Как считаем»; показатель, у которого хоть одна корзина с достаточным числом наблюдений выходит за допуск, не проходит, даже если Брайер лучше. Значение допуска и «достаточное число» определяет исполнитель и пишет их на той же странице;
    - решение «прошёл / не прошёл» принимается отдельно для каждой пары показатель × горизонт × позиция (GK/DEF/MID/FWD). Позиция, где данных меньше минимума, считается не прошедшей. В таблице игроков ячейка не прошедшей позиции показывает «—» с подсказкой, а не ноль;
    - не прошедший показатель скрывается с пояснением «показатель выключен: не лучше простой базовой линии», остальные показываются.
- **Переход v1 → v2.** Для очков v2 включается, только если проходит планку очков этапа 2 **и** не хуже v1 по MAE и ранговой корреляции на тех же турах. Иначе ожидаемые очки на следующий тур показываются по v1, а всё, что по очкам даёт только v2 (распределение очков, ожидаемые очки по матчам 2–5, разбивка двойного тура по матчам), скрыто: чтобы на карточке не стояли рядом два несогласованных числа. Вероятности гола, ассиста, старта и исхода показываются по v2 независимо от этого, если прошли свою планку.
- **Новые данные из FPL `event/{n}/live/`** (уже вызывается ради очков, один запрос на тур): `expected_goals`, `expected_assists`, `starts`, `goals_scored`, `assists`, `minutes`. Хранятся рядом с очками в `FplEventPoints` (или в соседней таблице — решает исполнитель). `penalties_order` из `bootstrap-static` — в `FplPlayerStatus`.
- **Форма «по матчам», а не по турам.** `event/{n}/live/` суммирует двойной тур. Для графика формы нужен разрез по матчам: либо `element-summary/{id}/` (по запросу на игрока, есть `fixture`, `expected_goals`, `starts`), либо разбивка по `explain` из live. Выбор за исполнителем; требование одно: двойной тур — два матча на графике.
- **Объяснение** — правила-шаблоны по компонентам модели и фактам, на английском, максимум 3 фразы, выбираются по вкладу в прогноз. У каждой фразы есть число.
- **Графики** — компонент `chart` из shadcn (на recharts), чтобы остаться в текущей дизайн-системе. Подписи осей с единицами, тултипы, переключатель периода там, где он осмыслен (форма: 5 / 10 / сезон). Прогнозные элементы — штрихованные или пунктирные, факт — сплошной.
- **Тёмная тема** — смена токенов в `globals.css` на весь сайт; переключатель темы не делаем (сайт тёмный).
- **Карточка остаётся публичной и бесплатной**, как страница игрока сейчас.
- **Кеш** — как у публичных страниц сейчас: прогнозы считаются ночной синхронизацией и читаются из базы.

## Найдено в коде и данных, важно для исполнителя

- Модель v1 уже считает частоты голов/ассистов на 90, P(выход), P(60+ минут), ожидаемые голы команды за и против — основа всех вероятностей. Хранит только итоговые очки и `components` (JSON) на тур.
- `Prediction` уникален по `(fplEvent, playerId, modelVersion)`: на матч, а не на тур, нужна новая таблица или расширение ключа.
- Оценка (`evaluation.ts`) уже walk-forward с калибровкой по позициям и планкой `BAR = { minEvents: 8, minPlayerEvents: 500 }`; `ModelEvaluation.details` — JSON, туда ложатся новые метрики.
- `PlayerMatchStats.isSubstitute` уже есть (API-Football): старт можно взять и из наших данных; FPL `starts` — для проверки.
- `Fixture.fplEvent` есть — матч привязан к туру FPL, двойные и пустые туры определяются по нему.
- Страница игрока (`src/views/stats/ui/player-profile-view.tsx`) и весь сайт сейчас на **английском**.
- Библиотеки графиков в проекте нет.
- Проверено 2026-11-16, без авторизации:
    - `bootstrap-static` отдаёт `expected_goals`, `expected_assists`, `starts`, `penalties_order`, `selected_by_percent`, окна фишек, `max_extra_free_transfers: 4`, `transfers_sell_on_fee: 0.5`; штрафа −4 в `game_settings` нет.
    - `event/{n}/live/` отдаёт по игроку за тур `expected_goals`, `expected_assists`, `starts`.
    - `element-summary/{id}/` отдаёт историю по матчам и ближайшие матчи.
    - Для следующего этапа: `entry/{id}/event/{gw}/picks/` (состав только прошедшего дедлайна), `entry/{id}/history/` (банк, стоимость, трансферы, фишки), `entry/{id}/transfers/` (цены покупки). Бесплатные трансферы и цены продажи только вычисляются.
    - Ограничений частоты в заголовках нет, ответы кешируются CDN на 5 минут.
    - API-Football `/odds`: Match Winner у ~10 букмекеров, «забьёт» только Bet365, рынка «ассист» нет. В этапе не используется.

## Риски

- Вероятности могут не пройти планку, особенно ассисты (редкое событие) и дальние матчи: тогда этот показатель скрыт, и карточка беднее, чем на макете. Это честное поведение, а не ошибка.
- xG FPL есть только за текущий сезон: до 8+ туров данных мало, вес xG в модели и графике формы ограничен.
- FPL — неофициальный источник; если пропадёт, вероятности по v2 работают на данных API-Football без xG, график формы показывает «нет данных xG».
- Перевод на тёмную тему может задеть старые экраны (конструктор, кошелёк, оплата): нужен визуальный проход по всем страницам.
- `element-summary` по запросу на игрока — ~700 запросов к неофициальному API за синк.

## Оставлено исполнителю

- Допуск калибровки и минимальный отрыв от базовой линии.
- Схема таблиц для прогнозов по матчам и новых данных FPL; миграция.
- Источник разреза «по матчам» для формы.
- Палитра тёмной темы в рамках «зелёный + фиолетовый», проверка контраста.
- Тексты шаблонов объяснений.
- Порядок реализации: данные → модель и проверка → карточка → таблица и матчи → тёмная тема (или тема первой, если удобнее).

## Результат проверки модели v2 (2026-11-18, первый прогон на реальных данных)

Миграция `20261116030000_add_probabilities` применена, `fpl-matches` отработал за два запуска (350 + 99 игроков, 4 425 строк, 0 ошибок; около 0,95 с на игрока), `probability` отработал за 6,5 с (2 380 строк по игрокам, 80 по матчам).

**Ни одна проверка пока не пройдена (0 из 42), поэтому на сайте вероятности скрыты, а карточка показывает факты и причины.** Так и задумано.

- **Событий для проверки мало.** Оценено 10 туров, но записи есть только по 5 (ближайший матч) и 4 (дальние): для базовой линии нужно не меньше 5 прошлых матчей игрока в данных FPL, а сезон только начался. Порог в 8 туров будет достигнут примерно к 13-му туру.
- **Цифры, которые уже видны.** Гол и ассист: у защитников, полузащитников и по всем вместе Брайер лучше базовой линии на 0,004–0,03 при 480–2 558 записях; без порога по числу туров они прошли бы. Старт: перекалиброван на высоких вероятностях (корзины 0,7–1), у нападающих хуже базовой линии. Распределение очков: у полузащитников хуже базовой линии. Исход матча: на дальних матчах хуже частот лиги, записей мало.
- **Очки v2 против v1** на одинаковых 2 112 записях: MAE 2,350 против 2,329, ранговая корреляция 0,229 против 0,248. v2 хуже, поэтому ожидаемые очки остаются по v1.
- **Скорость.** `probability` укладывается в минуту с большим запасом; узкое место ночного cron — `fpl-matches` (в бюджете 45 с успевает около 45 игроков при потребности 300–450 в сезоне).
