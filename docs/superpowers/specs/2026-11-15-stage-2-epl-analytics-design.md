# Этап 2 — Премьер-лига целиком: статистика, прогноз очков, конструктор, автосборка

Дата: 2026-11-15. Статус: черновик, ждёт одобрения.
Продолжает [этап 1](./2026-11-15-analytics-pivot-design.md) (он слит в `main`, PR #1). Общая цель и ограничения продукта описаны там и здесь не повторяются.

## Зачем

Заказчик хочет сайт, который собирает продвинутую статистику, глубоко её анализирует и с помощью алгоритмов и ИИ помогает собрать команду для игры на популярных fantasy-сайтах. Этап 1 убрал игру и подготовил платформу (кредиты, платный AI, чистая база). Этап 2 строит сам продукт для одной лиги: Английской Премьер-лиги и одной платформы, Fantasy Premier League (FPL).

## Что получает пользователь

- **Без входа** (открыто для поисковиков): таблица игроков с фильтрами, страница игрока (статистика, форма, прогноз очков на ближайший тур, цена), ближайшие матчи, страница «Как считаем» с честной точностью прогноза.
- **Со входом, бесплатно:** ручной конструктор состава по правилам FPL.
- **Со входом, за кредиты:** AI-разбор игрока (10), AI-прогноз матча (10), AI-разбор состава (30), автосборка (300).

Пользователь сам вводит готовый состав на сайте FPL. Никакого импорта, экспорта, привязки аккаунтов и планировщика трансферов нет.

## Цели

1. Загрузить в нашу базу расширенную статистику игроков АПЛ из API-Football: текущий сезон плюс предыдущий.
2. Держать актуальные цены и правила состава FPL и фактические очки FPL прошлых туров.
3. Считать прогноз очков игрока на ближайший тур собственной моделью и честно проверять её на прошлых турах.
4. Дать конструктор состава со всеми правилами FPL и сразу подсвеченными нарушениями.
5. Дать автосборку лучшего состава и AI-разбор состава за кредиты.
6. Публичные страницы статистики, которые индексируются поисковиками.

## Не цели

- Другие лиги и турниры (это этап 3).
- Планировщик трансферов, чипы FPL, история трансферов, прогноз изменения цен.
- Импорт и экспорт состава, привязка аккаунтов FPL.
- Прогноз на несколько туров вперёд: только ближайший тур.
- Своя модель xG.
- Редизайн интерфейса: текущий shadcn-дизайн и сайдбар остаются.
- Режим Kickbase и LaLiga Fantasy.

## Провал, даже если «работает»

- Пользователю показан прогноз, который не прошёл проверку точности (см. планку ниже).
- Конструктор или автосборка выдают состав, который сайт FPL не примет: нарушены позиции, бюджет, лимит клуба, размер состава.
- Автосборка списала 300 кредитов и не вернула состав, или списала дважды за один и тот же набор ограничений.
- Синхронизация затирает хорошие данные частичным или пустым ответом API (лимит запросов, ошибка, ответ без игроков) или молча перестаёт обновляться.
- Падение или закрытие доступа к FPL ломает публичные страницы вместо того, чтобы показать последние известные данные.
- Публичные страницы в обход кеша съедают суточный лимит API-Football.
- Секреты базы или API попадают в логи, код или публичные страницы.

## Решения заказчика

### Источники данных

- **API-Football** — единственный источник статистики для прогноза. Хранить статистику игрока в каждом матче (`/fixtures/players?fixture=ID`): минуты, рейтинг, голы, ассисты, удары и удары в створ, ключевые пасы, точность пасов, отборы, блоки, перехваты, единоборства, дриблинг, фолы, карточки, сейвы, пропущенные, пенальти. Загрузка: текущий и предыдущий сезон АПЛ (`league = 39`), около 800 запросов разово, потом только новые матчи. Суточный лимит тарифа заказчик не назвал (см. «Открытое»).
- **FPL API** (публичный, неофициальный, `bootstrap-static`, `event/{n}/live/`) используется для трёх вещей: цены игроков, правила состава (из `game_settings`: бюджет, размер состава, лимит клуба), фактические очки игроков за прошедшие туры **только для проверки точности прогноза**. Статистику, xG и собственные прогнозы FPL (`ep_next`) не берём.
- Весь код FPL живёт в одном адаптере. Если FPL закроет доступ или юрист запретит использование, адаптер отключается: конструктор работает без бюджета, проверка точности идёт по очкам, посчитанным нами самими из статистики, всё остальное продолжает работать.
- Сопоставление игроков API-Football и FPL: автоматически по имени, клубу и позиции; спорные пары правятся вручную в простой админке под `ADMIN_SECRET`.

### Синхронизация

- Скрипты в `scripts/`, запуск по расписанию в GitHub Actions: раз в сутки полная синхронизация (цены, очки, прогнозы), плюс короткий запуск каждые несколько часов в игровые дни (результаты, травмы).
- Те же скрипты запускаются вручную локально.
- В GitHub уже заведены секреты `STORAGE_DATABASE_URL`, `FOOTBAL_API_KEY`, `FOOTBAL_API_BASE_URL` (написание `FOOTBAL_` с одной «L» совпадает с кодом).
- Старые Vercel-кроны удалены в этапе 1 и не возвращаются.

### Прогноз очков

- Собственный алгоритм: ожидаемые минуты × показатели игрока на 90 минут × сложность соперника, пересчитанные в очки по актуальным правилам FPL, включая очки за оборонительные действия. У API-Football нет выносов (clearances), поэтому эти очки приближаются.
- Правила очков в коде: один конфиг, который проверяется сверкой с фактическими очками FPL (расхождение показывает неверное правило).
- Прогноз и автосборка на **один ближайший тур**.
- **Планка публикации:** прогноз лучше базовой линии «среднее очков за последние 5 матчей» одновременно по средней абсолютной ошибке и по корреляции рангов игроков внутри позиции, на ~10 прошлых турах, которых модель не видела при настройке. Если планка не взята: на страницах игрока показываются форма и статистика без прогноза, автосборка и платный AI-разбор состава не включаются.
- Точность (ошибка модели против базовой линии за последние туры) публично показывается на странице «Как считаем».

### Публичные страницы

- Без входа открыты: таблица игроков с фильтрами, страница игрока, ближайшие матчи, «Как считаем».
- Рендерятся на сервере и кешируются (не грузятся только в браузере), чтобы их индексировали поисковики и они не расходовали квоту API на каждый заход.
- Конструктор, AI и автосборка только после входа.

### Конструктор

- Состав как в FPL: 15 игроков (2 GK / 5 DEF / 5 MID / 3 FWD), стартовые 11 по выбранной схеме, 4 запасных в порядке замены, капитан и вице-капитан. Максимум 3 игрока из одного клуба, бюджет £100.0m. Размер состава, бюджет и лимит клуба берутся из `game_settings` FPL, а не прописываются.
- Рядом с каждым игроком: цена, прогноз очков на ближайший тур, статус травмы. Итог: потраченный и оставшийся бюджет, прогноз очков стартовой 11 с капитаном.
- Нарушения подсвечиваются сразу; сохранить можно только корректный состав.
- Несколько сохранённых составов на пользователя.
- Для игроков без цены (если адаптер FPL недоступен) бюджет не проверяется.

### Автосборка (300 кредитов) и AI-разбор состава (30 кредитов)

- Автосборка: алгоритм оптимизации с ограничениями (без LLM) собирает состав с максимальным прогнозом очков: 15 игроков, стартовая 11, скамья, капитан, вице-капитан, по правилам и бюджету FPL.
- До запуска пользователь может зафиксировать игроков, которых хочет оставить, и исключить тех, кого брать не хочет.
- Рядом AI-пояснение: почему эти игроки, где риск, чем заменить каждого. LLM состав не выбирает, только объясняет.
- Каждый новый набор ограничений стоит 300 кредитов; повторный запуск с тем же набором и тем же прогнозом бесплатен (из кеша). Результат открывается в конструкторе и там редактируется.
- AI-разбор состава: 30 кредитов, на состав из конструктора, кешируется по хешу состава и туру.
- Разбор игрока (10) и прогноз матча (10) остаются, их промпты обновляются на актуальные правила очков FPL.
- Списание кредитов и кеширование — по тому же правилу, что в этапе 1 (`docs/server-architecture.md`, раздел «Paid AI features»): сначала генерация, потом атомарное списание, ошибка генерации не списывает.

## Решения исполнителя (не обсуждались, можно оспорить)

- Несколько составов без жёсткого лимита на пользователя.
- Цены FPL меняются каждый день: в сохранённом составе храним цены на момент сохранения, показываем актуальные и отмечаем, что бюджет изменился.
- Админка сопоставления игроков остаётся простой страницей без редизайна.
- Статистика хранится по матчам (игрок × матч), а не только по турам: в туре бывает два матча у одной команды (double gameweek) и ни одного (blank gameweek).
- Матчи АПЛ (дата, статус, команды, счёт, номер тура) переезжают из «живых» запросов к API-Football в нашу базу: они нужны для сложности соперника, ожидаемых минут и расчёта по турам.
- **Как измеряется планка и когда она проверяется.** Прогноз на тур N считается только по данным до этого тура (walk-forward), поэтому отдельного «отложенного» набора не нужно. Настройка модели идёт на прошлом сезоне, где очки считаются нами из статистики API-Football и заведомо смещены (нет выносов и очков за оборонительные действия FPL), и эти очки помечаются как приблизительные. Сама планка судится **только по фактическим очкам FPL текущего сезона** (`event/{n}/live/` отдаёт только текущий сезон). Для оценки нужно не меньше 8 сыгранных туров; пока их меньше, планка считается не взятой и прогноз не публикуется. Оценка пересчитывается при каждой ночной синхронизации, результат хранится, и «прогноз включён» вычисляется из последней сохранённой оценки (живой выключатель, а не разовое решение). Оцениваются игроки, у которых ожидаемые минуты до тура были ≥ 30, одинаково для модели и базовой линии. «Лучше» означает положительный отрыв по обоим показателям; минимальный отрыв и проверка, что он не в пределах шума, определяет исполнитель.
- **Автосборка без цен.** Автосборка требует цен FPL не старше 3 суток. Если адаптер выключен или цены устарели, кнопка автосборки отключена с понятным текстом, а не продаёт состав, который может не пройти бюджет. Конструктор в этом случае работает без проверки бюджета, как в остальных решениях.
- **Привязка матча к туру.** Основной источник номера тура и события — FPL (его fixtures и events); номер тура из «раунда» API-Football хранится рядом как запасной и используется, когда адаптер FPL выключен. Перенесённые, двойные и пустые туры определяются по FPL. Фактические очки FPL для проверки привязаны к событию FPL.
- **Кеш автосборки и разбора состава.** Ключ кеша: хеш ограничений (для автосборки) или хеш состава (для разбора) плюс номер тура. Повторный запрос с тем же ключом в рамках тура бесплатен и отдаёт сохранённый результат. Если прогноз с тех пор обновился, результат показывается с пометкой «прогноз обновился», а новый платный запуск пересчитывает по свежему прогнозу. Для автосборки и разбора состава правило одинаковое. (Подтверждено заказчиком.)
- `Gameweek.number` уникален глобально. Для одной АПЛ это допустимо; для мультилиги в этапе 3 потребуется привязка к сезону лиги.
- Модель прогноза и всё FPL лежат в отдельных модулях (`src/server/prediction/`, `src/server/fpl/`) по общей схеме Controller → Service → Repository; регистрация в `container.ts`.

## Найдено в коде, важно для исполнителя

- `PlayerGameweekStats` хранит только минуты, голы, ассисты, сухари, сейвы, пенальти, пропущенные, карточки, автогол, очки. После этапа 1 в неё никто не пишет (сборщик был частью удалённого подсчёта очков). Для модели не хватает ударов, ключевых пасов, отборов, перехватов, дриблинга, рейтинга.
- Матчи не лежат в базе: `FixtureRepository` каждый раз ходит в API-Football.
- `PlayerSeasonPrice` (`seasonYear` Int, `priceSource`: `MANUAL` / `DERIVED` / `BACKFILL_HASH`) хранит выдуманные цены; новые цены FPL должны сюда или в замену писаться с `priceSource = 'FPL'`. Контроллер `/api/pricing/{seasonYear}` и админ-загрузка CSV остались от старой модели.
- `src/server/player-gameweek-stats/` и часть `GameweekService` (`syncFromApi`, `activateGameweek`, `finalizeGameweek`) недостижимы из роутов; их можно переиспользовать или удалить.
- `AiReport.kind` — произвольная строка; добавляются виды `SQUAD_REVIEW` и `AUTO_BUILD`.
- Текущие AI-промпты (`ai-generator.service.ts`) содержат устаревшие правила очков FPL: нет очков за оборонительные действия (в данных FPL уже есть поле `defensive_contribution`).
- `src/entities/team` (`LeagueScope`, `useAllTeams`) строит страницу игроков на клиенте через Suspense; для публичных страниц нужен серверный рендер.
- Мёртвый код и предупреждения линтера из этапа 1 перечислены в его отчёте (`docs/server-architecture.md`: пример с `fantasyTeamController`).
- `scripts/create-test-user.ts` выдаёт 10 000 кредитов в базу из `STORAGE_DATABASE_URL`: нужна защита от запуска на проде.

## Риски

- Квота API-Football: ~800 запросов на первую загрузку и ~10–20 в сутки дальше; лимит тарифа не известен.
- FPL — неофициальный источник; условия его использования для коммерческого сайта не проверены. Вопрос передаётся юристу вместе с Terms и Return Policy.
- Сопоставление игроков между источниками ошибается на однофамильцах и транслитерации.
- Холодный старт: новички лиги и игроки, перешедшие в клуб, почти без данных; модель должна честно показывать низкую уверенность или не давать прогноз.
- Double и blank gameweeks ломают наивный «один матч за тур».
- Планка точности может не взяться с первой попытки: этап 2 тогда не закончен, а модель дорабатывается.
- Публичные страницы привлекают ботов и парсеры: нужен кеш и ограничение частоты.
- Секрет базы в GitHub Actions даёт полный доступ к проду любому, кто может менять workflow; `main` надо защитить от прямых пушей.

## Оставлено исполнителю

- Конкретная модель прогноза (формула ожидаемых минут, сглаживание, учёт сложности соперника) и способ проверки без утечки будущего в прошлое.
- Алгоритм автосборки (ILP или аналог) и библиотека для него.
- Схемы таблиц и индексов для матчей, статистики по матчам, цен, очков FPL, прогнозов, оценок модели, сохранённых составов.
- Расписание и бюджет запросов синхронизации; восстановление после сбоя посреди загрузки (идемпотентные повторы).
- Стратегия кеша и инвалидации публичных страниц.
- Порядок реализации и разбиение на части: данные и синхронизация, модель с проверкой точности, публичные страницы, конструктор, автосборка и AI-разбор.
